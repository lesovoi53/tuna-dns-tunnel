# Проверка 0.1.0-rc1

23 октября 2026: 41 тест в Linux/WSL, все прошли, пропусков нет. Проверены конфигурация, сохранение/отмена черновика, маскирование ключей, экспорт и точное соответствие пресетов Lite, безопасное чтение архивов, занятый порт, чужие файлы и службы, права файлов, UFW/iptables с подменой команд, откат при сбоях, резервное копирование и сохранение остановленного состояния при обновлении.

`bash -n install.sh bin/tuna-dns` и запуск предварительного просмотра меню прошли.

Настоящие MasterDnsVPN Server `7de2476` и StormDNS Client проверены в отдельном Linux network namespace. Клиент установил DNS-туннель с двумя зонами и передал HTTP-запрос через него к тестовому серверу. Четыре сценария прошли:

1. Прямой выход.
2. Выход через тестовый SOCKS5 без авторизации.
3. Выход через тестовый SOCKS5 с логином/паролем.
4. Недоступный SOCKS5: запрос отклонён, прямого обхода не было.

Использованы только синтетические ключи и пароли. Для воспроизведения нужны бинарник StormDNS Client и его sample TOML (в серверный дистрибутив не входят):

```bash
sudo unshare -n bash
ip link set lo up
ip addr add 203.0.113.1/32 dev lo
PYTHONPATH=. python3 tests/native_smoke.py --server-archive assets/masterdns-amd64.tar.gz --client /absolute/path/stormdns-client --sample /absolute/path/client-sample.toml
exit
```

Документальный адрес существует только внутри изолированного пространства. Проверка loopback-назначения непригодна: исходное ядро его блокирует. Сеть хоста и службы при тесте не меняются.

**Ещё не проверено:** реальное применение UFW (проверено с подменой команд), остальные заявленные дистрибутивы на живых VPS, публичное DNS-делегирование нового сервера, импорт ссылок этой версии на физическом Android-устройстве и длительная работа. Fixture-тесты не заменяют эти проверки. Основные серверы X-Manager этим установщиком не изменялись.

Тестовый Linux StormDNS Client поддерживает стратегии 0–3 и отвергает 5 при запуске. Поэтому транспортный smoke использует стратегию 3; экспорт по требованию сохраняет стратегию 5 как на основных серверах. Передача данных с экспортированными настройками стратегии 5 на актуальном Android-клиенте в этом выпуске не проверена.

## Дополнительная проверка на выделенной VPS

После публикации архива проверена предоставленная владельцем VPS: Debian 13.7, amd64, Python 3.13.5, настоящие systemd и iptables. X-Manager отсутствует. На хосте уже были x-ui/Xray и systemd-resolved: установка привязала DNS-туннель к публичному IPv4 на UDP 53, не затрагивая loopback DNS и конфигурацию x-ui. До разрешённой перезагрузки PID x-ui оставался прежним.

- Полный опубликованный архив установился с ядром из комплекта; обе собственные службы active/enabled.
- Настоящий клиент установил туннель к установленной службе с двумя тестовыми зонами. HTTPS generate_204 прошёл через Direct, SOCKS5 без авторизации и SOCKS5 с авторизацией. Недоступный SOCKS5 не дал прямого обхода.
- Попытка смены на занятый UDP-порт завершилась откатом: прежняя конфигурация и работающая служба восстановлены.
- Обновление сохранило побайтово ключ, настройки, домены и изменённые параметры экспорта. Вручную остановленная служба и закрытое собственное правило firewall не включились автоматически.
- Резервная копия восстановила службу, конфигурацию и правило. Удаление с сохранением настроек и последующее восстановление также прошли.
- После разрешённой перезагрузки изменение boot ID подтверждено, обе службы и iptables-правило восстановились. Все четыре транспортных сценария повторно прошли. Упавших служб нет; ошибок туннеля в журнале текущей загрузки нет.

Проверка использовала прямое обращение клиента к авторитетному DNS-серверу. Тестовые зоны `.invalid` не делегированы в публичном DNS. Параметры ссылок после испытаний возвращены к исходным значениям, маршрут — Direct. Учётные данные VPS и ключи в репозитории отсутствуют.

Архив rc1 оставлен неизменным (SHA256 `a617d4236bafdaf9da300077b4fa32670b7b79e663f28ec9aceb6cda286193a2`). Его вложенная документация отражает состояние проверки на момент упаковки; этот раздел добавлен после испытания того же архива на VPS.

## Исправление редактора в 0.1.0-rc2

43 Linux-теста прошли без пропусков. Новые тесты сначала воспроизвели ошибки rc1: запрет удаления последнего домена и выход из редактора при неверном вводе. После исправления проходят удаление всех доменов в черновике, блокировка сохранения пустого списка без потери черновика, добавление нового домена и сохранение. На VPS выполнены все 5 тестов установленного интерфейса; настройки побайтово сохранены, службы туннеля и x-ui активны. Изменён только интерфейс; серверное ядро не менялось.
