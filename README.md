# TUNA DNS Tunnel

Отдельный установщик и консольное управление MasterDnsVPN: домены, шифрование, экспорт профилей TUNA/StormDNS и выход напрямую либо через SOCKS5.

Устанавливается на отдельный сервер **без X-Manager**. X-Manager, Xray, панели управления и SOCKS5-сервер в комплект не входят. Можно использовать прямой выход или указать уже существующий SOCKS5-прокси, в том числе с логином и паролем.

## Установка

Первая версия опубликована как предварительная. Проверены установка на VPS Debian 13 без X-Manager, передача HTTPS через туннель, Direct/SOCKS5, обновление, откат, восстановление и автозапуск после перезагрузки. Подробности и оставшиеся ограничения — в VALIDATION.md.

Поддерживаемые платформы: Debian 12/13, Ubuntu 24.04/26.04 LTS, amd64/x86_64, systemd, Python 3.11+. IPv4-прослушивание, по умолчанию UDP 53. Установщик не отключает чужие DNS-службы: если порт занят, установка прекращается.

```bash
sudo apt-get update
sudo apt-get install -y python3 ca-certificates curl iptables dnsutils qrencode
curl -fL -o tuna-dns-tunnel-0.1.0-rc2.tar.gz https://github.com/lesovoi53/tuna-dns-tunnel/releases/download/v0.1.0-rc2/tuna-dns-tunnel-0.1.0-rc2.tar.gz
curl -fL -o SHA256SUMS https://github.com/lesovoi53/tuna-dns-tunnel/releases/download/v0.1.0-rc2/SHA256SUMS
sha256sum -c SHA256SUMS
tar -xzf tuna-dns-tunnel-0.1.0-rc2.tar.gz
cd tuna-dns-tunnel-0.1.0-rc2
sudo bash install.sh
```

Выполняйте команды последовательно и продолжайте только после успешного завершения предыдущей. Полный архив содержит ядро; его SHA256 повторно проверяет установщик. `dnsutils` нужен для диагностики DNS, `qrencode` — только для QR-кода. При активном UFW используются его собственные правила; иначе требуется iptables. Правила SSH установщик не меняет. Firewall облачного провайдера настраивается отдельно: разрешите выбранный UDP-порт.

После установки меню открывается командой `sudo tuna-dns`:

```text
TUNA DNS Tunnel
[1] Ссылки подключения / QR-код
[2] Домены этого сервера
[3] Шифрование и ключ
[4] Выход в интернет — Direct / SOCKS5
[5] Параметры экспортируемых профилей
[6] Имя подключения и порт
[7] Управление службой
[8] Диагностика и журнал
[9] Обновление и резервные копии
[0] Выход
```

## Домены и профили

Пример делегирования: `n.example.org A <IPv4 сервера>`, `d.example.org NS n.example.org`, `d1.example.org NS n.example.org`. В Cloudflare адрес должен быть DNS only. Добавьте обе зоны в меню доменов. Для обычных публичных резолверов авторитетный сервер должен быть доступен на UDP 53; нестандартный порт полезен для прямого подключения и требует поддержки клиента.

- `stormdns://`: отдельная ссылка для каждой зоны.
- `tuna://`: одна ссылка со всеми зонами этого сервера.
- Выбор основного домена меняет порядок зон; в черновике можно удалить все домены и добавить новые. Сохранение требует хотя бы одного домена; ошибка ввода не сбрасывает черновик.
- Ссылки содержат ключ доступа. Пароль внешнего SOCKS5 в ссылки не включается.

Параметры экспортируемых профилей соответствуют X-Manager Lite v2026.10.23.2. Общие значения: `resolver_balancing_strategy=5`, сжатие upload/download `2` (LZ4), `rx_tx_workers=16`, `tunnel_process_workers=0` (автоматически), batch=8, окно ARQ=600, максимальный RTO=5 секунд.

| Профиль | Копии данных / setup | Кодирование | Upload MTU | Download MTU |
|---|---:|---|---|---|
| Жёсткая цензура | 4 / 4 | включено | 28–200 | 60–900 |
| Стандартный | 2 / 2 | выключено | 38–150 | 100–500 |
| Мобильный / скоростной | 1 / 2 | выключено | 38–150 | 100–500 |

Редактор позволяет менять резолверы, балансировку, дублирование, сжатие, воркеры, MTU, ARQ, ping и размер пачки для каждого пресета. Изменения вступают в силу в заново экспортированных ссылках. Они не меняют уже импортированные клиентские профили и не перезапускают сервер. Значения воркеров выше относятся к клиентским ссылкам.

Шифрование: методы ядра 0–5, по умолчанию AES-256-GCM (5). При смене метода длина текстового ключа проверяется, при необходимости предлагается новый ключ. Старые ссылки после смены ключа/метода нужно заменить.

## Маршрут и диагностика

Внешний SOCKS5 задаётся адресом и портом, с необязательной авторизацией. Если прокси недоступен или отклоняет пароль, автоматического перехода на Direct нет. SOCKS5 сам по себе не шифрует соединение между сервером туннеля и прокси.

Проверка выхода в меню проверяет выбранный маршрут самого сервера; это не проверка всей цепочки через DNS-резолвер клиента. Отдельно проверяются записи DNS. Журнал показывается с маскированием ключа и пароля; ядро запускается с уровнем WARN, поскольку INFO исходного ядра печатает ключ.

## Обновление и резервные копии

Скачайте и проверьте полный архив новой версии, распакуйте в новую папку, затем выполните в ней `sudo bash install.sh --update`. Также путь к новой распакованной версии можно указать в меню. Конфигурация, ключ, домены, параметры экспорта и остановленное состояние сохраняются. Обновление ядра использует закреплённую в новой версии контрольную сумму.

```bash
sudo tuna-dns backup
sudo tuna-dns restore /var/backups/tuna-dns-tunnel-ИМЯ.tar.gz
sudo tuna-dns service stop
sudo tuna-dns service start
sudo tuna-dns export --preset 1 --format tuna
```

Резервные копии содержат ключи и пароли: хранятся с правами 0600. Восстанавливайте только доверенные собственные копии. При ошибке изменения установщик пытается вернуть предыдущие файлы, состояние служб и собственное правило firewall; ошибка отката выводится явно.

Удаление доступно через управление службой: с сохранением настроек либо полное. Команда `sudo tuna-dns uninstall` сохраняет `/etc/tuna-dns-tunnel`; `sudo tuna-dns uninstall --purge` удаляет и настройки. Сохранённые резервные копии остаются. После удаления вернуть копию можно через `sudo bash bin/tuna-dns restore <путь>` из распакованного дистрибутива.

Собственные пути: `/etc/tuna-dns-tunnel`, `/usr/local/lib/tuna-dns-tunnel`, `/usr/local/share/tuna-dns-tunnel`, `/usr/local/bin/tuna-dns`. Служба: `tuna-dns-tunnel.service`; для iptables дополнительно `tuna-dns-tunnel-firewall.service`. Установщик не принимает чужие существующие файлы за свою установку.

## Разработка и проверки

`python3 -m unittest discover -s tests -v` — проверка конфигурации, экспорта, меню и операций установки с подменёнными системными командами. `bash bin/tuna-dns --preview` показывает меню без установки.

Результаты и границы проверки: [VALIDATION.md](VALIDATION.md). Сборка дистрибутива: `python3 scripts/package.py --core /path/to/masterdns-amd64.tar.gz`.
